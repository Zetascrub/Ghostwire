# Project map

A one-line purpose for every source, doc, tooling, and config file in this
repository, as a navigation aid. Generated by hand from the codebase as of
2026-08-13; re-generate/update the relevant section when files are added,
removed, or substantially repurposed rather than letting this drift.

Excluded as non-source: `poe-p4/build/` and `poe-p4/managed_components/`
(ESP-IDF build output and downloaded component dependencies), `.pio/`
(PlatformIO build cache), `diagnostic-collections/` (runtime output from
`tools/diagnostic_receiver.py`), and `.git/`.

Many `include/*_screens.h` / `src/*_screens.cpp` pairs follow one
consistent pattern documented in full at
[docs/screen-extraction.md](screen-extraction.md): the pair is **draw-only**
(rendering a screen from state it's handed by reference), while
`src/main.cpp` still owns the actual state, input handling, and any
hardware/service orchestration for that screen. That relationship is
implied by "screens" in the description below rather than restated every
time.

## `include/` + `src/`: firmware modules (Cardputer ADV, PlatformIO/Arduino)

Grouped by area; each row is a `.h`/`.cpp` pair unless noted otherwise.

### Core app / shared infrastructure

| Files | Purpose |
|---|---|
| `src/main.cpp` | The application entry point and orchestrator: owns almost all mutable state, `setup()`/`loop()`, input routing, and hardware/service wiring for every screen; the extraction docs above describe the ongoing effort to shrink it. |
| `app_screen.h` | The `Screen` enum: every distinct UI screen in the app, used throughout `main.cpp` and the screen modules to route drawing/input. |
| `branding.h` / `branding.cpp` | Product name/version constants and the built-in color theme palettes (selected in Settings, applied everywhere via shared color globals). |
| `screen_chrome.h` (impl in `main.cpp`) | Shared header/footer/status-icon drawing primitives every extracted screen module uses for a consistent look. |
| `operation_coordinator.h` / `.cpp` | Tracks which long-running radio/IO operation (if any) is active and enforces conflict policy between them; pure state/logic, unit-tested under `env:native`. |
| `terminal_buffer.h` (header-only) | Bounded line-history buffer for the byte-oriented terminal screens (SSH/Telnet/Socket Workbench), stripping ANSI CSI/OSC sequences. |
| `hid_presets.h`, `settings_names.h`, `familiar_phrases.h` | Header-only shared constant tables (label lists) used by both `main.cpp` and their respective screen modules. |

## `shared/protocol/`: cross-firmware shared headers (C, included by both the Cardputer and P4 builds)

| File | Purpose |
|---|---|
| `README.md` | Describes the versioned Cardputer<->P4 companion protocol this directory defines. |

| `scan_ports.h` | The shared "13 common ports" quick-scan list used by both the Cardputer's Port Scan screen and the P4's button-triggered scan. |
